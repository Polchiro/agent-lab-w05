# Rejection: proposed file-organization plan

I reject this plan as written. It goes beyond the task's authorized scope and makes decisions that require evidence or human approval.

- **Organizing everything in Downloads** is outside the selected task folder and could affect unrelated files. Work only in the named task folder and its designated output directory.
- **Deleting duplicates** is unacceptable without checking file contents and confirming that removal is authorized. Preserve originals and copies; report suspected duplicates for a person to review.
- **Treating `final2` as the latest approved version** assumes meaning from a filename. Compare the versions, keep both, and ask the owner which one—if either—is approved.
- **Filling missing values with guesses** invents facts. Preserve missing or uncertain values as supplied and flag them for review.
- **Publishing automatically** shares work externally without authorization. Prepare a local draft and wait for explicit approval before any publication.

An acceptable alternative is to confirm the exact input and output folders, inspect files without changing originals, organize copies only within the task's output folder, document duplicates and unresolved choices, preserve missing values, and leave publication to a separately authorized step.
